# SlowQuit

适用于 **macOS 14+、Apple Silicon** 的菜单栏工具。受保护应用的 **⌘Q** 需要长按确认，提前松手即可取消。

## 使用

1. 打开 `SlowQuit.app`，点击“打开辅助功能设置”。
2. 在“系统设置 → 隐私与安全性 → 辅助功能”中开启 SlowQuit。若列表中没有它，使用 `+` 添加当前运行的 `.app`。
3. 回到设置页，状态应自动变为“保护中”；也可以点击“重新检查”。
4. 在受保护应用中短按 ⌘Q，快捷键会被拦截；持续按住达到设定时长后，执行下面的混合触发规则。

### 长按完成后的行为

- 能确认应用菜单中存在**已启用、仅使用 Command+Q 的正常退出项**时，发送正常退出请求。
- 菜单读取失败、读取超时、项目被禁用、快捷键被改绑，或无法确认其含义时，向原目标应用发送一次完整的 **⌘Q 按下／松开事件**，保留应用自己的处理方式。
- 菜单检查在后台执行，单次调用带超时、整体查询有时间预算；达到长按时长后可能有短暂查询延迟。查询过程中切换应用、模式、名单或输入源会取消尚未发送的动作。
- 当前退出菜单名称采用保守的英文、简体中文和繁体中文匹配；其他名称无法确认时转发快捷键。不会仅因菜单项使用 Q，就认定它代表退出。
- 转发的是一次短按。若应用自身还要求长按或其他确认，它仍可不执行退出。发送成功不等于应用已执行动作。

默认长按 **1 秒**。菜单栏 → 设置中可以修改为 **0.3～5 秒**，步进 0.1 秒。所有设置自动保存，新时长从下一次长按生效。

- 默认“保护全部，排除指定应用”；访达在初始排除名单中。旧版本的排除名单会保留。
- 也可选择“仅保护指定应用”。两套名单独立保存，切换模式不反转名单含义；指定名单初始为空，此时所有应用立即响应 ⌘Q。
- 左右 Command 均支持，Caps Lock 不影响匹配。
- 达标前松开 Command 或 Q、切换前台应用、按下其他修饰键或快捷键、更改输入源、锁屏、睡眠及切换用户都会取消当前进度。
- 保护开启时，一次物理按键序列最多触发一次 ⌘Q。排除或未选中的应用在第一次按下时立即响应，后续重复事件仍被拦截，直到松开 Q，避免连续影响后面的应用。
- 松开 Q 后可以重新按下，不要求同时松开 Command。通过 ⌘Q 退出 SlowQuit 自身时，会等待物理 Q 松开再结束进程；点击菜单“退出 SlowQuit”仍立即退出。
- 长按状态直接根据拦截器收到的按下、松开和修饰键事件维护，不通过系统按键状态轮询判断已被拦截的 Q。监听或系统会话中断时取消当前操作，恢复后需要新的按下事件。
- 浮层显示应用图标、名称与进度，不抢焦点；可以关闭。
- macOS 26+ 的浮层使用原生 Liquid Glass，材质透明效果跟随系统外观与“降低透明度”等辅助功能设置；macOS 14、15 使用系统 HUD 材质。应用不单独设置玻璃透明度或背景着色。
- 应用可以显示保存确认或拒绝退出。SlowQuit 不强制结束进程。
- Ctrl+Command+Q 等带额外修饰键的组合、⌘Tab 切换器中的退出、应用菜单中的“退出”保持原行为。
- 暂停保护仅对本次运行有效。登录时启动默认关闭，可在设置中开启。
- 菜单栏和设置页显示“已拦截短按次数”，跨重启保存，设置页可清零。仅统计受保护的按键在达标前因松开 Q 或 Command 而取消的情况；重复事件、完成的长按、切换应用、系统状态和故障取消均不计入。
- 菜单栏使用原创单色 Q 圆环矢量图标，暂停、需要授权和异常具有对应状态变体。

SlowQuit 不记录、保存或上传按键内容，不需要联网。检测到安全键盘输入或监听中断时会显示“保护异常”，并尝试恢复。

本地系统日志包含保护流程的启动、取消原因与触发结果，供排查问题使用；不包含其他按键、输入文本或网页内容。

## 构建

需要 Apple Silicon Mac 和 Xcode 27（当前工程格式）。本次验证环境为 Xcode 27 / macOS 27，应用最低部署版本为 macOS 14。

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild -project SlowQuit.xcodeproj -scheme SlowQuit \
  -configuration Release -destination 'generic/platform=macOS' \
  -derivedDataPath build build

open build/Build/Products/Release/SlowQuit.app
```

也可直接用 Xcode 打开 `SlowQuit.xcodeproj`，选择 SlowQuit scheme 和 My Mac 运行。

工程仅构建 arm64，最低部署版本为 macOS 14。默认使用本地 ad-hoc 签名，不需要开发者账号。全局按键拦截和跨应用正常退出需要关闭 App Sandbox。

日常使用建议将构建产物复制到固定位置（例如 `/Applications`），再进行辅助功能授权并开启登录启动。ad-hoc 签名随代码变化可能失去原有授权；更新后若仍显示“需要授权”，在辅助功能列表中移除旧条目，再添加当前应用。

### 已开启辅助功能，却仍然需要授权

macOS 会校验授权条目关联的代码签名。旧版或调试版的条目即使开关显示为开启，也可能不匹配当前 Release 应用；单纯关闭再开启开关不会替换旧签名。

1. 在 SlowQuit 设置中点击“定位当前应用”，确认需要添加的 `.app`。
2. 打开“系统设置 → 隐私与安全性 → 辅助功能”，选中旧 SlowQuit 条目，点击 `−` 移除。
3. 点击 `＋`，重新选择刚定位的应用，开启开关。也可以将 Finder 中的应用拖入该列表。
4. 回到 SlowQuit 点击“重新检查”；如果系统尚未刷新，退出并重新打开应用。

必要时可以使用系统提供的 `tccutil reset Accessibility org.slowquit.SlowQuit` 清除 **SlowQuit 自身**的辅助功能记录，然后重新添加授权。这不会授予权限，也不会清除应用设置。

Debug 构建使用独立标识 `org.slowquit.SlowQuit.debug`，显示名称为 `SlowQuit Debug`，避免再覆盖 Release 的授权。当前本地版本使用 ad-hoc 签名；代码更新后仍可能需要重新授权。跨更新保留签名身份需要使用稳定的代码签名证书。

## 验证

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

Swift Package 测试与应用共用 `SlowQuit/Core` 源文件，无外部依赖。测试不安装全局事件监听或发送全局按键，也不会退出真实应用。覆盖时长边界、取消原因、跨应用重复事件、双模式及旧配置迁移、计数去重/清零/持久化、菜单语义判断，以及转发按键的标记、配对和键码保留。

需要辅助功能授权及真实桌面的验证步骤见 [MANUAL_TESTS.md](MANUAL_TESTS.md)。单元测试不能代替不同系统版本、全屏、多显示器和第三方应用退出流程的实测。

## 代码结构

- `SlowQuit/Core/`：可测试的长按状态机、双模式偏好、计数、菜单决策与转发事件构造。
- `QuitProtectionService.swift`：Quartz 事件拦截、计时、异步触发、目标捕获、权限与恢复。
- `QuitMenuInspector.swift`：带时间预算的辅助功能菜单检查，失败时回退到快捷键。
- `StatusIcon.swift`：原创 Q 圆环及状态变体的矢量绘制。
- `ProgressOverlay.swift`：不激活目标应用之外窗口的进度浮层、显示器定位。
- `SettingsView.swift`：中文设置、授权引导、保护模式、名单和短按统计。
- `SlowQuitApp.swift`：AppKit 生命周期与菜单栏入口。
- `LoginItemManager.swift`：`SMAppService` 登录启动状态。

当前版本不包含自动更新、安装包制作或公开分发所需的 Developer ID 签名、公证。
